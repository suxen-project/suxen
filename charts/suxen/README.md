# Suxen Helm chart

This chart installs the standard UI-capable Suxen image. The administration UI is
enabled by default and can be disabled at runtime with `config.uiEnabled=false`.
Official releases do not publish a separate `noui` image.

## Install

Install an immutable published version:

```sh
helm install suxen \
  oci://ghcr.io/suxen-project/suxen-chart \
  --version 1.0.0-rc.2 \
  --namespace suxen \
  --create-namespace
```

The default installation runs one replica with SQLite and a filesystem blob store on
a `ReadWriteOnce` persistent volume. It is suitable for a single-node deployment; do
not scale this topology horizontally.

The chart version and application image version are released together. Leaving
`image.tag` empty selects the chart's immutable `appVersion`. Override the tag only
when deliberately testing a different build.

Do not set `image.repository` to a registry this same Suxen instance serves. Its pods
would pull their own image through themselves, so a full outage — or deploying a new tag
while Suxen is down — could not recover, because the pull would have no backend. Use an
external or mirror registry with immutable tags, keep `image.pullPolicy: IfNotPresent`
so a cached image survives a registry outage, and supply `imagePullSecrets` when that
registry is private.

See the [operations guide](../../docs/operations/operations.md) before exposing the service. It
covers TLS ingress limits, credential rotation, backup/restore, and forward-only
database migrations.

## Production topology

Multiple replicas require PostgreSQL, a shared blob store, cluster mode, and explicit
bootstrap credentials. The shared blob store can use S3-compatible storage, GCS, or the
chart-managed PVC with `blobStore.shared: true` and `persistence.accessModes` including
`ReadWriteMany` (a volume every replica can reach, such as CephFS). The chart rejects a
partial distributed topology. `blobStore.shared` is an operator assertion: CI does not run
CephFS or NFS, so validate atomic rename, close-to-open visibility, replica loss, and paired
restore on the exact storage class and mount options. The automated distributed topology
uses PostgreSQL and MinIO.
It can create a CloudNativePG cluster and optionally install the operator, or use an
existing PostgreSQL Secret.

An object blob store does not make the default SQLite database disposable. For a
single-replica SQLite/object-storage deployment, keep `persistence.enabled: true`; the PVC
stores
the database and survives pod replacement. Switching an existing SQLite release from
filesystem blobs to object storage keeps the same claim mounted. The chart omits the data
PVC only when PostgreSQL and either S3 or GCS are configured, or when persistence is
explicitly disabled.
Deployments that mount this data PVC use the `Recreate` update strategy, so an upgrade
stops the old pod before a replacement can mount the single-writer volume. Fully shared
PostgreSQL and object-store deployments retain rolling updates.

```yaml
replicaCount: 3

database:
  bundled:
    enabled: true
    instances: 3

blobStore:
  existingSecret: suxen-storage
  secretKey: blobstore-url
  credentialsSecret: suxen-s3-credentials

bootstrap:
  existingSecret: suxen-bootstrap

config:
  cluster: true

persistence:
  enabled: false

podDisruptionBudget:
  enabled: true

cloudnative-pg:
  enabled: true
```

Set `cloudnative-pg.enabled=false` when the operator is already installed. For a
managed PostgreSQL service, disable `database.bundled` and set
`database.existingSecret`. S3 credentials use the standard AWS SDK environment
variables; `blobStore.credentialsSecret` imports every key from one Secret into the
Suxen container. GCS uses application default credentials. Set
`blobStore.gcsCredentialsSecret` to mount a service-account JSON key, or leave it empty
when application default credentials are available through the node environment.

## Required Secrets

Secrets are never generated by this chart.

| Value | Required keys | Purpose |
| --- | --- | --- |
| `database.existingSecret` | `database.secretKey` (default `database-url`) | PostgreSQL connection URL |
| `blobStore.existingSecret` | `blobStore.secretKey` (default `blobstore-url`) | `s3://` or `gcs://` blob-store URL |
| `blobStore.credentialsSecret` | AWS SDK variables such as `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_REGION` | S3 authentication |
| `blobStore.gcsCredentialsSecret` | `blobStore.gcsCredentialsKey` (default `credentials.json`) | Optional GCS service-account JSON key |
| `bootstrap.existingSecret` | `bootstrap.passwordKey` and `bootstrap.tokenKey` | Initial administrator credentials |
| `oidc.existingSecret` | `oidc.stateSecretKey` | Shared browser-login state secret |
| `serviceMonitor.bearerTokenSecret.name` | `serviceMonitor.bearerTokenSecret.key` | Token with `admin:stats:read` for Prometheus |

Example bootstrap and storage Secrets:

```sh
kubectl -n suxen create secret generic suxen-bootstrap \
  --from-literal=bootstrap-password='replace-with-a-strong-password' \
  --from-literal=bootstrap-token='replace-with-a-long-random-token'

kubectl -n suxen create secret generic suxen-storage \
  --from-literal=blobstore-url='s3://artifacts/suxen?region=eu-west-1'
```

For GCS, the URL can be set directly because it contains no credential. Mount a key only
when application default credentials are unavailable:

```yaml
blobStore:
  url: gcs://artifacts/suxen
  gcsCredentialsSecret: suxen-gcs
  gcsCredentialsKey: service-account.json
```

```sh
kubectl -n suxen create secret generic suxen-gcs \
  --from-file=service-account.json=/secure/path/service-account.json
```

For PostgreSQL, object storage, or `config.cluster=true`, the password must contain at least 12
characters and the token at least 24 characters. Placeholder values are rejected.
Bootstrap values are used only when the initial administrator is created. Editing the
Secret and restarting does not rotate an existing password or token; use the UI or API
to create replacement credentials.

## Authenticated metrics

`/metrics` requires a bearer token with `admin:stats:read`. Enabling the ServiceMonitor
therefore also requires an existing Secret containing that token:

```yaml
serviceMonitor:
  enabled: true
  interval: 30s
  bearerTokenSecret:
    name: suxen-metrics
    key: token
```

```sh
kubectl -n suxen create secret generic suxen-metrics \
  --from-literal=token='replace-with-a-scoped-suxen-token'
```

The Secret is referenced by the ServiceMonitor and is not mounted into the Suxen pod.
Create the Suxen user/token before Prometheus begins scraping, or use the bootstrap
token temporarily and rotate to a scoped token afterward.

## Declarative provisioning

Set `provisioning.enabled=true` and provide either an inline document or an existing
ConfigMap. The chart mounts the selected key at
`/etc/suxen/provision/desired-state.yaml` and sets `SUXEN_PROVISION` for startup
reconciliation.

```yaml
provisioning:
  enabled: true
  document: |
    apiVersion: suxen.io/v1
    resources:
      - kind: role
        name: publisher
        spec:
          privileges:
            - repository:raw:write
      - kind: user
        name: automation
        spec:
          admin: false
          roles: [publisher]
          secretRef:
            env: AUTOMATION_PASSWORD

      # Blob-store attributes are reconciled like every other provisioned field.
      # This example is intentionally aggressive for a space-constrained store.
      - kind: blobStore
        name: constrained
        spec:
          driver: fs
          configurationRef:
            env: SUXEN_CONSTRAINED_BLOBSTORE
          attributes:
            uploadSessions:
              staleAfter: 15m
              maxStagedBytes: 5368709120
              maxPrincipalStagedBytes: 1073741824
              maxPrincipalSessions: 2
  environmentSecrets:
    - name: suxen-provision-environment
```

Secrets remain outside the ConfigMap. `provisioning.environmentSecrets` exposes Secret
keys as environment variables for `secretRef.env`. Entries in
`provisioning.secretMounts` mount a Secret at an absolute path for `secretRef.file`.
See [the provisioning guide](../../docs/operations/provisioning.md) for resource schemas, pruning,
and secret-resolution rules.

Startup reconciliation is leader-gated with multiple replicas and never prunes.
Inline document changes update a pod-template checksum. Kubernetes does not restart
pods when an external ConfigMap or Secret changes, so restart the Deployment after
updating `provisioning.existingConfigMap`, `environmentSecrets`, or `secretMounts`:

```sh
kubectl -n suxen rollout restart deployment/suxen-suxen
```

OCI repository `endpoints.hosts` and `endpoints.ports` in an inline
`provisioning.document` are the process configuration and the chart source for extra
Service ports and extra Ingresses. `ingress.ociHosts` adds only TLS and annotations.
`service.extraPorts` and `ingress.extraHosts` are for `existingConfigMap` or
imperative repositories; combining them with inline endpoints fails the render.

## Important values

| Value | Default | Description |
| --- | --- | --- |
| `replicaCount` | `1` | Fixed replica count when autoscaling is disabled |
| `image.repository` | `ghcr.io/suxen-project/suxen` | Standard UI-capable image. Do not point at a registry this same instance serves (see below) |
| `image.tag` | chart `appVersion` | Image tag override |
| `image.pullPolicy` | `IfNotPresent` | Lets a node reuse a cached image, so a pull is not required to recover from a registry outage |
| `imagePullSecrets` | `[]` | Pull secrets for `image.repository`, e.g. an external private registry |
| `service.port` | `8080` | External primary Service port; it always targets the pod's fixed `http` port on 8080 |
| `persistence.enabled` | `true` | Create a PVC for SQLite metadata and/or filesystem blob storage |
| `blobStore.shared` | `false` | Assert the filesystem PVC is `ReadWriteMany` and reachable by every replica, allowing multi-replica without object storage (sets `SUXEN_BLOBSTORE_SHARED`) |
| `blobStore.gcsCredentialsSecret` | `""` | Optional Secret containing a GCS service-account JSON key |
| `blobStore.gcsCredentialsKey` | `credentials.json` | Key selected from `blobStore.gcsCredentialsSecret` |
| `bootstrap.user` | `admin` | Initial administrator username used with the bootstrap password or token |
| `database.bundled.enabled` | `false` | Create a CloudNativePG cluster |
| `config.cluster` | `false` | Enforce PostgreSQL/shared-storage cluster topology and singleton leases |
| `config.uiEnabled` | `true` | Serve embedded UI routes |
| `config.maxUploadBytes` | `10737418240` | Per-upload byte limit |
| `config.maxConcurrentUploads` | `4` | Concurrent upload budget per replica |
| `config.authFailureLimit` | `10` | Failed credential verifications allowed per direct peer and window |
| `config.authFailureWindow` | `1m` | Authentication failure counting window |
| `config.authLockout` | `5m` | Per-peer credential-verification lockout |
| `config.authTrustedProxyCIDRs` | `[]` | Proxy networks trusted to supply the authentication client chain |
| `config.readTimeout` | `0` | Overall HTTP request read deadline; `0` permits long streaming uploads while headers retain a 10-second deadline |
| `config.writeTimeout` | `0` | Overall HTTP response write deadline; `0` permits long streaming downloads |
| `config.cleanupInterval` | `1h` | Cleanup-policy scheduler interval; `0` disables policy cleanup |
| `config.gcInterval` | `1h` | Blob garbage-collection interval; `0` disables scheduled GC |
| `config.verifyInterval` | `0` | Blob integrity-verification interval; `0` disables scheduled verification |
| `config.migrateInterval` | `1m` | Draining blob-store migration interval; `0` disables scheduled migration |
| `config.webhookRetryBase` | `1s` | Initial webhook retry delay, doubled after each failed attempt |
| `config.webhookPollInterval` | `1s` | Interval at which the delivery worker claims due webhook deliveries |
| `config.webhookMaxAttempts` | `8` | Failed webhook delivery attempts before dead-lettering |
| `config.proxyManifestTTL` | `5m` | Tagged OCI proxy revalidation interval |
| `config.outboundTimeout` | `30s` | Overall OIDC and webhook request timeout |
| `config.proxyResponseHeaderTimeout` | `30s` | Proxy upstream response-header wait; proxy bodies stream without an overall deadline |
| `resources.limits.memory` | `1Gi` | Per-replica memory limit sized for four concurrent near-limit npm publish requests; validate custom limits with the capacity harness |
| `autoscaling.enabled` | `false` | Create an HPA; requires the distributed topology |
| `ingress.enabled` | `false` | Create an Ingress |
| `ingress.ociHosts` | `{}` | TLS/annotations for OCI hosts derived from `provisioning.document` |
| `ingress.extraHosts` | `[]` | Extra Ingresses when the provision document is not inline |
| `service.extraPorts` | `[]` | Extra Service ports when the provision document is not inline |
| `serviceMonitor.enabled` | `false` | Create an authenticated Prometheus ServiceMonitor |

Review [`values.yaml`](values.yaml) for the complete values surface.

Authentication failure tracking is local to each pod and uses the direct socket peer
unless `config.authTrustedProxyCIDRs` trusts that peer's network. A trusted ingress
must overwrite or safely append `X-Forwarded-For`; do not trust arbitrary client-facing
networks. Keep the throttle values identical across replicas. Without trusted proxy
CIDRs, clients routed through one ingress share each pod's limit. Size the limit for
the topology and alert on the authentication failure and blocked-attempt metrics.

When ingress is enabled, configure TLS, a body-size limit above
`config.maxUploadBytes`, and proxy timeouts for the largest intended transfer. The
[operations guide](../../docs/operations/operations.md) includes an ingress-nginx example.

## Validate and upgrade

Render production values before applying them; validation failures describe unsafe or
incomplete combinations:

```sh
helm lint charts/suxen -f production-values.yaml
helm template suxen charts/suxen -f production-values.yaml >/tmp/suxen-rendered.yaml
```

Upgrade chart and image together by pinning the new chart version:

```sh
helm upgrade suxen \
  oci://ghcr.io/suxen-project/suxen-chart \
  --version 1.0.0-rc.2 \
  --namespace suxen \
  --values production-values.yaml
```
